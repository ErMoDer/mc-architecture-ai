# 充能与激活：强弱电、供电 vs 激活（Java）

**用途**：把玩家理论里的「强/弱充能」「给方块供电 vs 激活组件」收成建筑 AI / 模板匹配能用的规则。加深 [basics.md](basics.md) §3，避免只背口诀。

**版本**：~1.13 起的充能框架在 **26.3 仍适用**（粉尘 0～15、中继器顶方块等）。新组件（铜灯泡、合成器、幽匿）的「怎样算被激活」以该组件页 + [version-diffs.md](version-diffs.md) 为准。

## 1. 三个易混词

| 词 | 指什么 | 例子 |
|----|--------|------|
| **信号强度** | 0～15 的数值 | 粉尘亮度、比较器输出 |
| **充能（powering）** | 某个**实心方块**或粉尘处于「带电」状态 | 中继器顶着方块 → 该方块被**强充能** |
| **激活（activating）** | 执行器**开始工作** | 活塞伸出、发射器开火、红石灯亮 |

口诀：**先充能，再谈会不会激活**；QC 则是「激活检查多看了一格」（见 [qc-bud.md](qc-bud.md)）。

强度对多数执行器**只有有/无**：活塞收到 1 与 15 伸出行为相同；强度主要用于比较器、模拟信号、粉尘传多远。

## 2. 强充能 vs 弱充能（实用版）

| | **强充能** | **弱充能** |
|--|------------|------------|
| 常见来源 | 中继器/比较器输出端顶实心块；部分电源直接作用 | 粉尘「点到」实心块侧面等 |
| 对该方块邻接粉尘 | 更容易把**四周粉尘**点亮（可向外传导） | **往往不能**再点亮该方块另一侧的粉尘 |
| 对组件 | 方块被强/弱充能都可能激活贴在上面的火把/门等（看组件规则） | 同左，但「经方块传导粉尘」弱一截 |

建筑向检查：

1. 要「穿过方块继续走线」→ 用**中继器对着方块输出**（强充）。  
2. 粉尘贴在方块上只为点灯/激活邻接组件 → 弱充常常够用。  
3. 调试「线断了」时先看：是不是弱充方块指望它再带对面粉尘。

## 3. 供电路径速查（模板匹配用语）

| 写法（报告/注释） | 含义 |
|-------------------|------|
| `soft_power_block` | 弱充实心块，不指望它向外导粉尘 |
| `hard_power_block` | 强充实心块，可向外导粉尘 |
| `direct_component` | 粉尘/火把/中继器直接对着执行器 |
| `qc_above` | 依赖上方充能（Java 活塞/发射器等） |

不要把 `hard_power` 写成「伤害更高」——只表示传导能力。

---

## 4. 激活检查（执行器）

不同组件「怎样算被激活」不同：

| 组件 | 激活直觉 |
|------|----------|
| 红石灯 / 门 / 活板 | 自身或规定邻接被充能 |
| 活塞 / 发射器 / 投掷器 | 自身充能 **或** QC（上方） |
| 漏斗 | 被充能 → **锁定**（停运） |
| 铜灯泡（1.21+） | **脉冲边沿**翻转，持续电平不会连闪（详见 components） |
| 合成器（1.21+） | 需要**新脉冲**才产出一次 |

模板必须写清：要的是**电平**还是**脉冲**。把拉杆当脉冲用是常见设计错误。

---

## 5. 对建筑 AI 的约束

**可用**

- 生成/分析时区分：装饰灯（可不通电）vs 机房走线（必须 hard/soft 标注）。  
- 预留「中继器顶方块」的 1 格厚度，而不是默认粉尘贴墙。  
- 标签：`power_style=pulse|level`、`needs_repeater_boost=true`。

**不可用 / 不可宣称**

- 不可在体素里随机洒粉尘并声称「已强充」。  
- 不可自动推导完整 soft/hard 图；复杂传导用人工模板。  
- 不可把强弱充能与「红石伤害/爆炸强度」类比进用户文案。
