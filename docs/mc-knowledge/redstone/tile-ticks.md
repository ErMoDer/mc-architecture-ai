# 计划刻 / Tile ticks（Java，中级）

**用途**：区分「红石 tick」与「方块计划刻」，方便分析报告与简化仿真对齐。不实现原版计划刻队列。

**版本**：计划刻机制长期存在；**具体哪些方块登记何种延迟**随版本微调。1.13 讲解的大框架可用；落到 26.3 时对水流、农作物、铜氧化等以 Wiki + 实测为准，见 [version-diffs.md](version-diffs.md)。

**来源（改写摘要）**

## 1. 三条时间线（不要混）

| 名称 | 量级 | 管什么 |
|------|------|--------|
| **Game tick（gt）** | 1/20 s | 游戏主循环 |
| **Redstone tick（rt）** | 2 gt | 中继器档位、多数红石延迟口语 |
| **Tile / scheduled tick（计划刻）** | 按方块登记的 gt 延迟 | 水/岩浆流动、农作物生长判定、部分方块「稍后再算」 |

红石时钟「1 tick」默认指 **rt**。说「水流要等几 tick」往往指 **计划刻**，不是中继器拨档。

---

## 2. 计划刻在干什么（直觉）

1. 某事件发生（放水、更新农作物、闪电氧化等）；  
2. 引擎把「某坐标的某方块在 N 个 gt 后再处理」丢进**计划队列**；  
3. 到期执行：可能流动、掉落、变状态，并可能再触发[方块更新](block-updates.md)。

与中继器的差别：中继器延迟是**红石组件状态机**；计划刻是**世界方块日程表**。

---

## 3. 和建筑 / 农场模板的关系

| 场景 | 计划刻意识 |
|------|------------|
| 室内水景 / 电梯水流 | 流动不是瞬时铺满；跨 tick 才稳定 |
| 甘蔗/竹子农场 | 生长有随机计划；观察者看的是**生长带来的更新** |
| 铜氧化 | 未涂蜡铜随时间计划变化；电路若「看氧化」需观察者，且勿当精确时钟 |
| 冰/雪相关装饰 | 融化/形成也可能走计划刻（维度与亮度条件另说） |

建筑 AI 外壳生成**不必仿真**计划刻；标 `has_fluid=true` / `farm_growth_observer=true` 即可。

---

## 4. 简化仿真（本项目允许的上限）

若分析器做 tick 对齐，最多：

- 红石：按 rt 累加中继器/比较器延迟；粉尘同 tick 传播。  
- 流体：标注「非瞬时」，不逐步模拟流动格子。  
- 生长：标注「随机计划刻」，不预测下一棵甘蔗时刻。

禁止宣称「与原版计划刻队列 bit 级一致」。

---

## 5. 对建筑 AI 的约束

**可用**

- 文档与报告区分 `delay_rt` vs `scheduled_gt`。  
- 农场模板注明依赖观察者/计划生长，而非红石钟「精确同步作物」。  
- 水流机关：模板实测后锁定，不旋转到未验证方向。

**不可用 / 不可宣称**

- 不可让模型「发明」依赖精确计划刻竞态的电路。  
- 不可用计划刻解释一切 QC 问题（那是更新/充能，见 qc-bud）。  
- 不可把 TNT 炸链、破基岩教程当建筑生成默认知识（片单 P2，优先级低）。
