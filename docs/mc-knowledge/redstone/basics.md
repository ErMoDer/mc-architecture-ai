# 红石入门：信号、时间与基本组件（Java）

用盖房的人能看懂的话讲清楚：电从哪来、走多远、慢几拍、常用零件干什么。  
默认 **Java**；和基岩版不一样的地方会点一下。目标环境仍是 companion 的 **26.3**（红石主干规则与 1.21.x 一致）。

---

## 1. 两套「时间」

游戏主循环是 **20 次/秒**：

| 名称 | 长度 | 怎么记 |
|------|------|--------|
| **Game tick（gt）** | 0.05 秒 | 游戏最小节拍 |
| **Redstone tick（rt）** | 2 gt = 0.1 秒 | 红石人口语里的「1 tick 延迟」常指这个 |

中继器拨到「1」= **1 rt = 2 gt = 0.1 s**；拨到「4」= **4 rt = 8 gt = 0.4 s**。

> 和朋友说延迟时，先约定说的是 **红石 tick** 还是 **游戏 tick**，避免差一倍。

---

## 2. 信号强度（0～15）

- 红石信号是 **0～15** 的整数。0 = 没电；15 = 满。
- **强度一般不改变「能不能推动」**：活塞收到 1 和收到 15，伸出距离和速度一样；红石灯亮不亮也不看强度（有电就亮）。
- 强度有用的场景：比较器比较/减法、模拟信号（物品数量、堆肥桶层数）、粉尘传播距离。

### 粉尘（红石线）

- 相邻粉尘传信号，**每经过 1 格粉尘，强度 -1**。
- 满电最多传 **15 格**粉尘，第 16 格为 0。
- 粉尘本身更新可视为 **0 延迟**（同一 game tick 内传开；复杂 QC/活塞链另说）。

要传更远：中间加 **中继器** 或 **比较器**（比较器保持后侧强度，不「加满」）。

---

## 3. 强充能 vs 弱充能（直觉版）

社区常说 strong / weak power：

| 类型 | 直觉 | 典型后果 |
|------|------|----------|
| **弱充能** | 粉尘「点亮」了某个实心方块 | 这个方块**旁边的粉尘**可能不会被带亮（取决于朝向与连接） |
| **强充能** | 中继器/比较器输出端「顶着」实心方块，或部分组件直接强充 | 该方块四面的粉尘更容易被点亮 |

入门够用的口诀：

1. **粉尘接到组件侧面/背面** —— 先看组件说明。  
2. **要可靠地点亮「方块后面的线」** —— 常用中继器对着方块输出。  
3. 活塞、发射器等：只要被充能（含准连接 QC）就会动，细节见待写的 `qc-and-bud.md`。

## 4. 电源从哪来

| 组件 | 特点 |
|------|------|
| 拉杆 / 按钮 / 压力板 / 绊线钩 | 玩家或实体交互；按钮有固定按下时间 |
| 红石块 | 一直 15；**不**强充能周围实心方块的「传导」方式与粉尘不同，但对相邻组件可直接供电 |
| 红石火把 | 附着面没电时亮；有电时灭（逆变）；会烧毁（高频闪） |
| 阳光传感器 | 白天/夜晚（反转模式）给模拟强度 |
| 探测铁轨、绊线、熔炉是否燃烧等 | 场景电源 |
| 观察者 | 「看见」方块状态变化 → 发出短脉冲 |
| 容器 + 比较器 | 按装满程度输出 0～15 |

## 5. 三大传输/逻辑件

### 中继器（Repeater）

- 背面有电（任意强度）→ 正面输出 **强度 15**。
- 延迟：1～4 红石 tick（2/4/6/8 game tick）。
- **锁存**：侧面被另一个中继器或比较器供电时，锁定当前输出（开或关保持）。
- 还会「拉长」过短的开脉冲（延迟档位越高越明显）——做时钟和脉冲整形时很重要。

### 比较器（Comparator）

- 固定延迟：**1 rt（2 gt）**。
- 模式（右键切换）：
  - **比较模式**（前线灯关）：后侧强度 ≥ 两侧较大值 → 输出后侧强度；否则输出 0。
  - **减法模式**（前线灯开）：输出 = 后侧 − 两侧较大值（≥0）。
- **测量**：对着容器（箱子、漏斗、熔炉、堆肥桶、蛋糕等）可读「满度」→ 0～15。
- 不做「加满到 15」；要续航距离用中继器。

### 观察者（Observer）

- 正面检测方块更新，背面输出 **短脉冲**（Java 上常见为 1 rt 量级脉冲，精确边沿待写电路篇复核）。
- 非常适合：甘蔗/竹子生长、活塞移动、门开关等「变化就脉冲」。
- 注意：观察者互相盯着容易自激振荡。

---

## 6. 火把与逆变

- 红石火把：附着的方块**未被充能**时点亮，充能时熄灭 → 天然 **NOT**。
- 火把烧掉：闪太快会暂时失效——高频时钟优先用中继器/观察者/比较器时钟，而不是狂闪火把。

## 8. 版本差异要点（红石向）

| 版本 | 点 |
|------|----|
| 历史长期 | QC、活塞更新顺序是 Java 特色；基岩版很多电路不能直接搬 |
| 1.11+ | 观察者成为稳定积木 |
| 1.14+ | 目标方块（箭矢信号）等 |
| 1.19 | 幽匿传感器：振动当信号；羊毛/地毯可遮振 |
| 1.21 | **合成器**：红石脉冲弹出合成结果；可做自动工厂建筑 |
| 1.21 | 活塞音量调低——功能不变 |
| 26.x | 红石主干未改「15 格粉尘 / 中继器 1–4 rt」这套；新方块是否传导以该版为准 |

不确定的具体 bug 修复标 **待核实**，以当前 26.3 实测为准。

## 9. 对建筑 AI / 导出

1. **朝向（facing）是状态，不是「换方块名」**。当前体素若只存 ID、不存 state，门/中继器/活塞会朝向错误。  
2. 生成「红石房间」时，优先保证：电源 → 线 → 中继器续航 → 执行器（活塞/灯/门）的 **空间走线**，而不是随机洒粉尘。  
3. 机械与外壳可分离：Litematica 一层建筑 + 一层已验证的红石模板。  
4. 高频装置注意实体与客户端卡顿——生存可玩性优先于极致 tick 优化。
